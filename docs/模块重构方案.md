# fnGate · 证书与 DNS 模块重构方案

> 版本：v2.2（已实施 P1 + P2）　｜　对应：v1.0.2 → v1.2.0
> 目标：把「证书管理 + ACME 任务」两个混装模块拆成 **证书管理 / ACME 任务 / DNS 服务商 / 域名解析** 四个职责单一的模块。

---

## 1. 现状与问题

v1.0.x 把证书相关能力压成两页：

| 页面 | 实际承担的内容 |
|---|---|
| 证书管理 | 证书列表、上传、详情、引用关系、设为默认 |
| ACME 任务 | DNS 服务商管理、ACME 账户、签发订单、手动 TXT 记录 |

四个具体问题：

1. **DNS 服务商被埋在弹窗里**。想单独测试某个服务商是否还有效，必须先打开「ACME 任务 → 申请证书 → 下一步」，路径深且不符合直觉；也无法回答「这个 Token 被哪些证书用着」。
2. **证书没有主分类**。证书多了以后只能靠肉眼扫表格，自动签发与手动上传混在同一列表里。
3. **故障排查全靠外部工具**。`could not determine authoritative nameservers` 这类报错的根因在 DNS 侧，产品内看不到 NS、SOA、CNAME 的实际返回。
4. **模块边界与后端不一致**。后端 `acme` 包同时管凭据、账户、订单，前端却按两页切分。

## 3. 模块一 · 证书管理

### 3.1 分类方式：两个维度

只做两个维度，主分类做成 tab，状态只做筛选。

**维度 A：来源（主分类，tab 切换，自动派生）**

| tab | 含义 |
|---|---|
| 全部 | 不筛选 |
| ACME 申请 | 由本应用签发并自动续期 |
| 手动上传 | 用户上传的证书 + 私钥 |
| 自签证书 | 应用内生成的自签名证书 |
| 飞牛系统证书 | 从 fnOS 系统证书目录接入 |

tab 上带数量角标，例如「ACME 申请 3」。

**维度 B：状态（筛选下拉，按 `not_after` 实时计算）**

| 值 | 规则 |
|---|---|
| 全部状态 | 不筛选 |
| 有效 | 剩余 > 30 天 |
| 即将到期 | 0 < 剩余 ≤ 30 天 |
| 已过期 | 剩余 ≤ 0 |
| 文件缺失 | 证书链或私钥文件不可读 |

阈值复用设置里的「证书续期提前天数」，不写死。

**不做用户自定义分组**：不引入 `group` 字段，也不做分组管理页。多个筛选条件（来源 + 状态 + 关键词）叠加即可满足日常查找。

### 3.2 页面结构

```
┌ 统计条（可点击，联动状态筛选）──────────────────────┐
│ 证书总数 12 │ 30 天内到期 2 │ 已过期 1 │ 飞牛系统证书 3 │
└──────────────────────────────────────────────────────┘
┌ 筛选工具条 ──────────────────────────────────────────┐
│ [全部 12][ACME 3][手动 5][自签 1][飞牛 3]  [状态下拉][搜索] │
└──────────────────────────────────────────────────────┘
┌ 表格 ───────────────────────────────────────────────┐
│ 名称/主域名 │ SAN │ 来源 │ 签发者 │ 有效期 │ 状态 │ 操作 │
└──────────────────────────────────────────────────────┘
```

- 点击统计条「30 天内到期 / 已过期」直接切换状态筛选，下拉框同步更新。
- tab 与状态下拉、搜索框三者叠加过滤，切换时只重绘表格，不重新请求接口。
- 筛选后无结果时给出「当前筛选没有匹配的证书」空态，而不是复述「证书库是空的」。
- 行内操作不变：详情 / 重命名 / 设为默认 / 下载 / 续期 / 删除。

### 3.3 详情弹窗

分三段：证书信息（主体 / SAN / 签发者 / 序列号 / 指纹）、来源与续期（ACME 任务链接、上次续期结果、下次检查时间）、关联（引用的反代规则）。

## 4. 模块二 · ACME 任务

只保留**订单**语义，DNS 服务商管理入口已移出。

- 顶部：「申请证书」主按钮 + 一个次要的「DNS 服务商」按钮（跳转到新页面，不再内嵌管理）。
- 列表列：状态、域名、CA / 验证方式、时间、说明、操作。
- 进行中的订单：状态徽标 + 最后一条日志摘要。
- 失败订单：说明列直接显示可读原因；详情里折叠「错误详情」（服务商原始报错）。
- 保留：ACME 账户管理、自动续期证书列表。

申请向导保持三步（域名 → 服务商/CA → 确认），「服务商」步骤只从已配置列表里选，空列表时提示去「DNS 服务商」页添加。

## 5. 模块三 · DNS 服务商（已实施）

### 5.1 页面结构

```
┌ 统计条 ──────────────────────────────────────────────┐
│ 服务商 2 │ 校验通过 1 │ 校验异常 1 │ 可管理域名 7 │
└──────────────────────────────────────────────────────┘
┌ 表格 ───────────────────────────────────────────────┐
│ 名称/类型 │ 账号 │ 状态 │ 可管理域名 │ 引用 │ 操作 │
└──────────────────────────────────────────────────────┘
```

- 「名称 / 类型」：名称加粗，下方类型徽标（阿里云 / DNSPod / Cloudflare / 手动）。
- 「账号」：脱敏后的凭据标识（如 `12345,ab***`），用于区分同类型的多个账号。
- 「状态」：绿=最近一次校验通过（附时间），红=失败（附原因，超长省略），灰=未校验；手动模式显示「无需凭据」。
- 「可管理域名」：读取到的域名数量 + 「查看域名」入口。
- 「引用」：被几张证书、几个进行中任务使用。
- 操作：测试连接（结果落库）、编辑（改名称或覆盖凭据）、删除。

### 5.2 交互细节

- **添加**：类型 → 凭据字段动态渲染 → 「测试连接」可就地验证 → 保存时后端再跑一次同一套只读校验，不通过直接拒绝入库。
- **编辑**：类型锁定，凭据字段全部留空表示沿用现有值；只填要改的字段，避免要求用户重新粘贴全部密钥。
- **查看域名**：抽屉列出账号下真实存在的域名，每行提供「用此域名申请证书」直达申请向导（预填 `example.com, *.example.com`）。
- **删除**：被证书用于自动续期、或有进行中订单时返回 409 并列出具体证书名，不做级联删除。

### 5.3 数据模型

```go
type DNSProvider struct {
    ID            string `json:"id"`
    Type          string `json:"type"`      // alidns | dnspod | cloudflare | manual
    Name          string `json:"name"`
    CredentialRef string `json:"credential_ref"`
    AccountHint   string `json:"account_hint"`    // 脱敏账号标识
    LastCheckAt   string `json:"last_check_at"`
    LastCheckOK   bool   `json:"last_check_ok"`
    LastCheckMsg  string `json:"last_check_msg"`
    ZoneCount     int    `json:"zone_count"`      // 0 表示尚未读取
    CreatedAt     string `json:"created_at"`
}
```

`AccountHint` 在后端保存时生成，前端永远拿不到明文凭据。

### 5.4 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/dns/providers` | 列表（含校验状态与引用数） |
| POST | `/api/dns/providers` | 新增，保存前自动校验 |
| PUT | `/api/dns/providers/{id}` | 改名 / 覆盖凭据 |
| DELETE | `/api/dns/providers/{id}` | 有引用时 409 |
| POST | `/api/dns/providers/verify` | 未保存凭据的测试连接 |
| POST | `/api/dns/providers/{id}/verify` | 已保存凭据的测试连接，结果落库 |
| GET | `/api/dns/providers/{id}/zones` | 该账号下的域名（只读） |
| GET | `/api/dns/types` | 表单字段元数据 |

原来挂在 `/api/acme/providers*` 的路由已移除；前端资源带版本号，不存在旧页面继续调用的问题。

## 6. 模块四 · 域名解析（已实施）

一期只做只读，二期再开放写操作。

### 6.1 查询

```
┌ 查询 ───────────────────────────────────────────┐
│ [example.com          ] [TXT ▾]  [查询]          │
│ 服务器：[系统 ▾] 223.5.5.5  119.29.29.29  ...    │
└─────────────────────────────────────────────────┘
┌ 结果 ───────────────────────────────────────────┐
│ 每台 DNS 一行：响应码、答案、耗时                  │
└─────────────────────────────────────────────────┘
```

- 一次查询**同时打多台 DNS**（系统 + 223.5.5.5 + 119.29.29.29 + 8.8.8.8 + 1.1.1.1，可在设置里改），并排展示差异——这是判断「是否传播完成」最直观的方式。
- 支持 CNAME 跟随开关，展示「查询名 → CNAME 链 → 最终答案」。
- 记录类型：`A / AAAA / CNAME / TXT / NS / SOA / MX / CAA`。

### 6.2 体检（一键诊断）

输入域名后串行跑 6 条规则，每条返回 `通过 / 警告 / 失败` + 说明 + 建议：

| # | 检查项 | 判定 | 失败提示 |
|---|---|---|---|
| 1 | NS 委派 | apex 能列出 NS | 域名可能未正确指向当前 DNS 服务商 |
| 2 | 权威 NS 可解析 | NS 主机名能解析出 IP | 权威服务器域名解析失败，CA 一定校验不过 |
| 3 | 区域顶点 NS 查询 | apex 的 NS 查询有 Answer | **v1.0.1 故障**：该 DNS 不返回 apex NS，签发需用「递归校验」 |
| 4 | SOA 一致性 | 各 DNS 返回的 SOA 序列号一致 | 解析尚未同步到所有服务器 |
| 5 | 多 DNS 一致性 | 各服务器对 A / TXT 的回答一致 | 部分 DNS 仍有旧缓存 |
| 6 | `_acme-challenge` 形态 | 无 CNAME，或 CNAME 目标明确 | 存在通配 CNAME，TXT 将被带到别处 |

第 3、6 条对应已经踩过的两个坑，做成常驻检查项。

### 6.3 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/dns/resolvers` | 服务器候选（系统 / 公共 / 自定义）与默认勾选 |
| POST | `/api/dns/resolve/query` | 多服务器并发查询，返回每台的响应码、答案、耗时 |
| POST | `/api/dns/resolve/diagnose` | 6 条规则体检，每条带状态与建议 |

两个 POST 都是只读的纯查询，不接触凭据、不写状态文件。

### 6.4 实现要点

- 与签发链路共用 `dnsExchange / findZone / apexNameservers`，保证「这里看到的」与「签发时用的」是同一份事实。
- 查询按服务器并发（上限 8 台），结果按传入顺序排列，便于并排比对；单台超时 5 秒，UDP 截断自动改 TCP 重试。
- 一致性判定把回答排序后比对签名，出错（无响应）的服务器不参与比对，避免「一台挂了就说传播没完成」。
- 「跟随 CNAME」= 回答里只有 CNAME 时补查链尾同类型记录；关闭则只展示原始回答。
- 体检第 2 条额外识别权威 NS 解析到 `198.18.0.0/15` / `0.0.0.0`（Clash / Surge fake-ip 劫持），这类环境 CA 必然连到假地址。

### 6.5 二期：记录管理

- 通过已配置的服务商增删改 `A / AAAA / CNAME / TXT`。
- 二次确认 + 变更前后 diff + 审计日志。
- 默认只对「本应用签发的 `_acme-challenge` 记录」开放删除。

## 8. 代码结构调整

```
src/
  acme/
    manager.go     # 签发编排
    api.go         # /orders /accounts /config /overview
    dnsapi.go      # DNS 服务商模块（NewDNSModule）+ 解析查询路由，挂 /api/dns/
    resolve.go     # 新增：多服务器查询与 6 条体检
    verify.go      # 三家只读探测
    dnspod.go      # 自研 DNSPod provider
    nscheck.go     # 传播校验策略探测
  cert/            # 证书管理（未改后端，分类在前端完成）
  static/js/
    cert.js        # 来源 tab + 状态筛选
    acme.js        # 瘦身为订单
    dns.js         # DNS 服务商页
    resolve.js     # 新增：域名解析页
```

`DNSAPI` 与 `API` 是同一包内的两个 `api.Module`，分别挂到 `/api/dns/` 和 `/api/acme/`。前端拿到的是独立路由前缀与独立页面，模块边界成立。

P2 落地后仍保持同包：`resolve.go` 直接复用了 `findZone`、`apexNameservers`、`dnsExchange` 这些已经服务于签发链路的实现。如果按原计划下沉到 `src/dnsp/`，这些函数要连同 `Store`、`Settings` 一起抽接口，改动面大于收益，且会让「签发看到的」和「体检看到的」有分裂风险。**物理拆包延后到 P3**，届时若要支持第三方调用再评估。

- `/api/dns/*` 八个路由全部可用；`/api/acme/providers*` 已下线（404）。

- 真实域名 `666086.xyz`：NS 查询三台 DNS 均返回空 Answer 且 authority 段为 `SOA f1g1ns1.dnspod.net`，与历史故障一致；TXT 两条记录齐全。

## 10. 取舍与风险

| 决策 | 取舍 |
|---|---|
| 证书只做「来源 tab + 状态筛选」 | 不引入自定义分组与标签；代价是无法按业务线归档，靠搜索补足 |
| DNS 服务商与 ACME 同包、不同模块 | 复用凭据校验与探测逻辑，避免两套判定标准；代价是目录上暂未物理拆分 |
| 域名解析一期只读 | 避免写操作误删风险；代价是用户仍需去控制台加记录（ACME 已自动加） |
| 新增字段不写迁移脚本 | 零值即兼容；代价是旧数据首次打开时状态列显示「未校验」，需手动点一次测试连接 |
| 旧 `/api/acme/providers` 不保留兼容层 | 前端资源带 `?v=VERSION` 强刷；代价是外部脚本若直接调用会 404 |
