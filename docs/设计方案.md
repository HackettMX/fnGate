## 0. 事实基础

### 0.1 已从参考项目源码确认

| 项 | fnUPnP | fnReverseProxy |
| --- | --- | --- |
| 形态 | fnOS Native `.fpk`，Go 单二进制，**无 Docker** | 同左 |
| 管理通道 | 统一网关 Unix Socket（`app.sock`），**不监听管理 TCP 端口** | 同左 |
| 桌面入口 | `gatewayPrefix=/app/fnportgate` + `gatewaySocket=app.sock` | `/app/fnproxy` + `app.sock` |
| 运行身份 | `run-as: package`（非 root） | `run-as: root` → `setcap cap_net_bind_service` → `runuser` 降权 |
| 业务端口 | 无（只管路由器 NAT 表） | 按规则监听 HTTP / HTTPS / TCP（含 80/443） |
| 存储 | `$TRIM_PKGVAR/fnportgate.json` 原子写 | `$TRIM_PKGVAR/rules.json` 原子写 |
| 前端 | 原生 HTML/CSS/JS + `go:embed`，零构建 | 同左 |
| 打包 | 三架构静态编译 → `fnpack build -d fpk` → `fix_fpk_perms.py` 修权限位/校验和 → `.fpk` | 同左 |
| 发布 | GitHub Actions `v*` tag → Release | 本地 `build.sh` |

两条已验证的工程结论直接继承：

1. 管理面必须走统一网关 Socket（`protocol: ""` + `control.accessPerm: "hidden"`），否则 HTTPS 访问飞牛时 iframe 混合内容白屏。
2. Windows 下 `fnpack` 会丢 Unix 执行位，必须二次重打包修权限位并重算 `manifest.checksum`（= `app.tgz` 的 MD5）。

### 0.2 来自公开资料、尚未在目标机型实测

- fnOS 系统证书索引：`/usr/trim/etc/network_cert_all.conf`，网关证书映射 `/usr/trim/etc/network_gateway_cert.conf`（内容形如 `{"host":"example.com","cert":"...","key":"..."}`）；证书实体在 `/usr/trim/var/trim_connect/ssls/<domain>/<timestamp>/<domain>.crt|.key`。
- 证书由 `network_service` 管理，单纯 `nginx -s reload` 不生效。
- `go-acme/lego` 支持 ACME v2、DNS-01/HTTP-01/TLS-ALPN-01、`*.example.com` 泛域名与多域名合并签发、200+ DNS 提供商（含阿里云、腾讯云 DNSPod、Cloudflare、华为云）、多 CA。

> 以上需实现前在真实 fnOS 上做一次 Spike 验证（见 D2、D3）。

## 1. 产品定位

一款 fnOS 原生应用，把「**公网入口 → 内网服务 → HTTPS 证书**」这条链收进一个界面：

| 模块 | 解决的链路环节 |
| --- | --- |
| 路由端口转发 | 公网 → NAS：UPnP IGD 管理路由器 NAT 映射 |
| 反向代理 | NAS → 内网服务：HTTP/HTTPS/TCP 按域名 + 路径分流 |
| 证书管理 | HTTPS 身份：飞牛证书 / ACME 泛域名 / 手动上传 / 自签，统一供给反代 |

**合并的价值不是把三个页面并排，而是联动**：新建反代入口后可「一键发布到公网」自动生成 UPnP 映射；证书续期后所有引用它的反代入口零重启自动生效；概览页能一眼看到「哪个域名 → 哪个端口 → 哪张证书 → 是否生效」。

## 2. 总体架构

```
                    飞牛桌面图标（同源 iframe）
                            │  统一网关 /app/fngate
                            ▼
                 ┌──────────────────────────┐
                 │  app.sock（唯一管理通道）  │
                 └────────────┬─────────────┘
                              ▼
   ┌─────────────────────────────────────────────────────────┐
   │  fnGate 单进程（Go 静态二进制，Native .fpk）               │
   │                                                          │
   │  ┌──────────┐  ┌──────────┐  ┌────────────────────────┐  │
   │  │ forward  │  │  proxy   │  │ cert                    │  │
   │  │ UPnP IGD │  │ Listener │  │ 列表/上传/飞牛导入      │  │
   │  │ 映射管理 │  │ Route    │  │ ACME(DNS-01)/自动续期  │  │
   │  │ 自动补发 │  │ Manager  │  │ CertificateResolver    │  │
   │  └────┬─────┘  └────┬─────┘  └───────────┬────────────┘  │
   │       └─────────────┼────────────────────┘               │
   │              core：State / EventBus / Scheduler / Log      │
   │              api：REST + 内嵌 WebUI（go:embed）            │
   └───────┬─────────────────────┬─────────────────────────────┘
           │ SSDP/SOAP           │ 业务监听 80/443/自定义端口
           ▼                     ▼
      路由器 NAT 表        内网后端 192.168.x.x:port
```

单进程三子系统，共享一份状态、一个事件总线、一个调度器。管理面与业务面分离：管理面只经 Unix Socket 暴露，业务面只监听用户显式配置的端口。

## 3. 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 语言/构建 | Go 1.23+，`CGO_ENABLED=0` 静态编译 | 与两个参考项目一致，三架构交叉编译无 glibc 依赖 |
| Web | 标准库 `net/http` + `httputil.ReverseProxy` | 沿用已验证方案，不引入 Caddy/Nginx 外部进程 |
| UPnP | `github.com/huin/goupnp`（IGD1/IGD2） | 平移 fnUPnP 的 514 行封装（含错误码中文化、负缓存、网关指纹保护） |
| ACME | `github.com/go-acme/lego`（库模式） | 唯一能同时覆盖泛域名 DNS-01、多 CA、多 DNS 商的成熟 Go 库 |
| 存储 | 单 `state.json` + `schema_version` + 原子写 + 备份 | 数据量小；比多文件更易做备份/迁移/一致性 |
| 私钥/凭据 | 独立 `secrets/` 目录（0700 / 文件 0600） | 与可导出的配置分离 |
| 前端 | 原生 HTML/CSS/ES Module + `go:embed`，零构建 | 沿用；按模块拆分 JS，不再单文件堆砌 |
| 打包 | `fnpack` 双层 tar.gz + 权限修正脚本 | 沿用 |

## 4. fnOS 运行形态与权限模型

### 4.1 关键配置（拟定）

```ini
appname="fngate"
version="0.1.0"
display_name="路由网关"
platform="all"
source="thirdparty"
os_min_version="0.9.0"
ctl_stop=true
checkport=false
disable_authorization_path=true
desktop_uidir="ui"
desktop_applaunchname="fngate.main"
```

`app/ui/config`：`protocol: ""`、`gatewayPrefix: /app/fngate`、`gatewaySocket: app.sock`、`control.accessPerm: hidden`、`allUsers: true`。

### 4.2 权限：本方案最需要决策的一处

fnGate 同时需要两件「特权」：绑定 80/443，以及读取 fnOS 系统证书私钥。参考项目只解决了前者。

| 方案 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| A（推荐） | `run-as: root` 启动 → `setcap` → `runuser` 降权；系统证书由 **root 侧 helper** 在启动/定时同步为应用私有快照 | 主进程非 root；证书可读 | 多一个受控 helper（见下） |
| B | 全程 root 运行 | 最简单，读写无阻 | 面向网络的进程持 root，安全面差 |
| C | `run-as: package` | 最安全 | 绑不了 80/443，读不到系统证书，两个核心能力降级 |

**推荐 A 的落地方式**：主二进制提供 `--cert-sync` 子命令，`cmd/main` 以 root 调用它读取 `/usr/trim/etc/*.conf`，把证书对复制到 `$TRIM_PKGVAR/certs/fnos/`，`chown` 给应用用户、`0600`；主进程降权后只读快照，不接触系统路径。UI 的「同步飞牛证书」按钮触发一次受控 helper 调用（固定参数、白名单路径、不接收任意文件路径，避免提权）。

> 若 Spike 发现系统证书私钥本身对普通用户可读，则 helper 可简化为直接读取，方案 A 仍成立。见 D2。

### 4.3 生命周期

`cmd/main start|stop|status`：架构探测（`uname -m` → amd64/arm64/arm，失败逐个 `--version` 试跑）→ 目录权限准备 → `setcap` → 降权 → `setsid` 拉起 → `--probe-socket` 真实握手确认就绪；`status` 返回 0/3。
`install/upgrade/uninstall_init|callback` 负责升级前备份 `state.json` 与 `secrets/`、schema 迁移、卸载时按 wizard 选项清理。
`wizard/uninstall` 增加提示：证书私钥、ACME 账户、DNS 凭据属于敏感数据，删除后不可恢复；路由器上已生效的映射不会被自动删除。

## 6. 模块一 · 路由端口转发

平移 fnUPnP 的成熟实现，保留：SSDP 自动发现（IGD1 WANIP/WANPPP + IGD2）、公网 IP 微缓存、发现失败负缓存、UPnP 错误码中文化（718 端口冲突等）、「本应用托管 / 其他设备添加」双列表、网关指纹变化或枚举失败时暂停自动补发、路由器重启后自动补回。

新增（与另两个模块的联动）：

- 添加映射时可从 **反代入口下拉选择**，自动填入内部端口与本机 LAN IP，避免手抄。
- 反代入口详情页提供「一键发布到公网」：选外部端口 → 生成映射 → 立刻校验生效状态。
- 映射记录带 `source_ref`，反代入口改端口/删除时给出「关联映射待更新」提示，不擅自改路由器配置。
- 概览页展示公网 IP、网关型号、映射生效数、最近一次补发结果。

## 7. 模块二 · 反向代理（重构重点）

### 7.1 沿用技术方案

单进程 HTTP/HTTPS/TCP 三类代理、`Host` + 路径前缀路由、端口手动添加且 1 对多、TLS 按 SNI 选证书、TCP 按 SNI/单规则端口兜底、后端健康探测、规则 JSON 持久化、绑定失败可见化。

### 7.2 数据模型重构：从「扁平规则」到「入口 + 路由」两层

| 现状（fnReverseProxy） | 重构后 |
| --- | --- |
| 每条规则都带 `listen_port` + `protocol`，同端口多域名要重复填 | `Listener` 管端口/协议/TLS，`Route` 只管域名/路径/后端 |
| 同端口混协议靠保存时 409 拦截 + 运行时再判一次 | 模型上不可能产生（路由只能挂在唯一入口下） |
| 证书靠手填 `cert_file` / `key_file` 路径 | `cert_id` 引用证书库，入口级默认 + 路由级覆盖 |
| 域名单值、只支持精确匹配 | `domains[]`，支持 `*.example.com` 泛域名与精确域名混用 |
| 保存任意规则 → 重建**全部**监听，断连约 1 秒 | 增量 Apply：只重建受影响的 Listener；纯 Route 变更零重启 |
| TLS 配置在 Reload 时一次性构建，证书更新需重建监听 | `GetCertificate` 每次握手向 `CertificateResolver` 查询，续期后零重启生效 |

### 7.3 引擎改进

- `Manager.Apply(changeSet)`：按 listener 维度做 diff，新增/删除/更新分别处理；失败回滚到上一版监听，已建立连接不受影响。
- `CertificateResolver` 按 SNI 解析顺序：路由级精确域名 → 入口默认证书 → 泛域名证书 → 自签兜底；缓存 + 文件 mtime 变更检测。
- 健康检查：TCP / HTTP 状态码双模，可配间隔与超时；状态与「未生效原因」聚合到入口和路由。
- 访问日志/错误日志落盘并可在 UI 查看（带轮转），未命中规则、后端不可达不再静默。
- 保留低端口能力检测与 `--check-bind` 自检（复用 fnReverseProxy 脚本逻辑）。

### 7.4 界面重构

| 现状问题 | 改法 |
| --- | --- |
| 单页一张表，无导航 | 左侧三模块导航 + 概览/设置；统一顶栏状态 |
| 长表单一次铺开 12 个字段，无分组无实时校验 | 分步/分组表单（基础 → 匹配 → 后端 → 策略 → 证书），实时校验与错误定位 |
| 证书只能填文件路径 | 证书选择器（显示 SAN、剩余天数、来源、被引用数）+ 跳转证书模块 |
| 无端口视角，看不出「一个端口挂了哪些域名」 | 入口列表 → 展开路由的二级视图，端口状态/证书/路由数一目了然 |
| 状态只有一列小圆点 | 入口状态条（监听中/端口被占用/无权限/证书缺失）+ 未生效原因聚合提示 |
| 无搜索、筛选、批量操作 | 按域名/端口/状态筛选，批量启停、批量删除（二次确认） |
| 无引导 | 空状态引导「先建入口 → 再加路由 → 需要 HTTPS 就选证书」 |

功能边界建议（v1 内置，见 D6）：HTTP→HTTPS 重定向、HSTS、WebSocket 开关、自定义请求头、`X-Forwarded-*`、超时、后端 TLS 校验开关、路径剥离。访问控制、限流、WAF、多后端负载均衡列为后续。

## 8. 模块三 · 证书管理（全新）

### 8.1 四种来源

| 来源 | 说明 |
| --- | --- |
| `manual` | 上传 PEM 证书链 + 私钥；校验密钥匹配、链完整性、解析 CN/SAN/有效期 |
| `fnos` | 读取飞牛系统证书库（只读导入，见 8.3） |
| `acme` | 自动申请，支持泛域名，见 8.4 |
| `selfsigned` | 自签兜底，仅用于内网/临时，明确标注「不受浏览器信任」 |

### 8.2 证书列表

名称、主域名、SAN（含泛域名标记）、来源、签发者、生效/到期时间、剩余天数（正常/临期/过期三色）、状态、被引用数（点开看哪些入口/路由在用）、操作（详情、下载、立即续期、重新申请、设为默认、删除）。删除被引用证书时阻止并列出引用位置。

### 8.3 接入飞牛证书

- 启动时/用户点击「同步」时，由 root 侧 helper 解析 `/usr/trim/etc/network_cert_all.conf` 与 `network_gateway_cert.conf`，多路径探测 + JSON/JSONL 兼容解析，复制 crt/key 到应用私有目录。
- 列表里标注「飞牛系统证书 · 只读」，展示 host 与到期时间；可在反代里直接选用。
- 解析失败或路径变更（fnOS 升级）时明确提示并降级为「手动上传」，不静默显示空列表。
- **v1 不做回写**：不修改飞牛系统证书库、不改 `network_service` 配置、不动其数据库（见 D3）。

### 8.4 ACME 申请

- CA：Let's Encrypt（默认，提供 staging 开关）、ZeroSSL（需 EAB）、Buypass / 自定义 ACME Directory。
- 挑战：**DNS-01 为主**（泛域名唯一可行方式，一张证书可同时含 `example.com` 与 `*.example.com`）；单域名可选 HTTP-01 / TLS-ALPN-01（需 80/443 可用）。
- DNS 提供商：可插拔接口，v1 内置阿里云 DNS、腾讯云 DNSPod、Cloudflare（+ 视 D4 结果增补华为云等）；另提供 **手动 DNS-01 模式**——无 API 凭据时展示需添加的 `_acme-challenge` TXT 记录，用户手动添加后点「验证」，覆盖长尾 DNS 商。
- 密钥：ECDSA P-256 默认，可选 RSA 2048/4096；账户私钥与域名私钥分存，续期可选轮换。
- 申请流程做成**后台任务 + 实时进度**：创建订单 → 展示待添加 TXT → 自动/手动完成 → 轮询校验 → 签发 → 原子落盘 → 加入证书库 → 触发 Resolver 刷新 → 若关联入口则自动应用。UI 可查看任务日志、重试、取消。
- 先在 Let's Encrypt staging 验证流程，再切生产，避免触发速率限制。

### 8.5 自动续期

- 调度器每日低峰随机窗口检查；默认到期前 30 天续期（可配），优先参考 CA 的 ARI 窗口。
- 失败按指数退避重试（1h / 6h / 24h，上限 24h），连续失败在概览页与证书列表红色告警。
- 续期成功保持 `cert_id` 不变，通过版本目录 + 原子切换更新证书链与私钥；所有引用自动生效，**零重启、零断连**。
- 续期期间旧证书继续服务；新证书校验失败则回滚并告警。

### 8.6 在反代模块应用证书

入口表单的「HTTPS 证书」选择器读取证书库，按 SAN 与入口域名做匹配推荐（泛域名证书自动命中子域名）；路由级可覆盖。保存后 `Manager` 仅刷新该 listener 的 TLS 解析，不重建 TCP 监听。

### 8.7 安全

`secrets/` 0700、文件 0600；DNS Token / ACME 账户密钥不回显前端（只返回 masked）、不入日志、不入普通配置导出；导出备份时对私钥单独提示；管理 API 校验同源 / 拒绝跨站写操作（见 D8）。

## 9. 模块联动（本应用的核心差异）

1. **一键发布**：反代入口 → 「发布到公网」→ 自动填 UPnP 映射（内部端口 = 入口端口）→ 回显公网访问地址。
2. **证书自动应用**：申请/上传/续期证书 → 按 SAN 提示「可应用到这些入口」→ 一键绑定；续期后所有引用自动生效。
3. **全局健康视图**：概览页聚合路由器连接、监听端口状态、映射生效数、证书最近到期天数、未生效项与失败任务，点击直达对应模块。
4. **一致的错误语义**：端口被占用、证书缺失/过期、映射未生效、ACME 失败都在事件总线上汇总，不静默。

## 13. 打包与发布

1. `scripts/build.sh <version> [arch]`：`GOOS=linux CGO_ENABLED=0` 交叉编译 `amd64 / arm64 / arm(GOARM=6)`，`-trimpath -s -w -X main.version=...`，`platform="all"` 单包通吃。
2. `fnpack build -d fpk` → `fix_fpk_perms.py`（显式写 `0755/0644`，重算 `checksum`）→ `dist/fngate-<version>.fpk`。
3. CI（GitHub Actions）：`v*` tag → `go vet ./...` + `go test ./...` → 三架构编译 → 下载 fnpack → 打包 → `softprops/action-gh-release` 发布 Release。
4. 验证：fnOS 应用中心「设置 → 手动安装」上传 `.fpk` → 桌面图标打开 → 三模块冒烟 → 升级/卸载留数据验证。
5. 发布分三层，需明确本次目标（见 D9）：**① 本地 `.fpk` 产物** → **② GitHub Release 公开下载** → **③ 飞牛应用中心上架**（官方表单 + 截图 + 审核，人工流程）。
6. 升级：`upgrade_init` 备份 `state.json` + `secrets/`，`upgrade_callback` 执行 schema 迁移；静态资源版本号保证不会出现「新 HTML + 旧 JS」。

## 15. 风险清单

| 风险 | 缓解 |
| --- | --- |
| fnOS 系统证书路径属内部实现，版本升级可能变化 | 多路径探测 + 兼容解析 + 失败降级为手动上传；实现前 Spike 实测 |
| 降权后读不到系统证书私钥 | root helper 快照方案；Spike 先验证文件权限（D2） |
| ACME 速率限制 / DNS 传播延迟 | staging 先行、DNS 传播轮询 + 可配 resolver、退避重试 |
| DNS API Token 与私钥泄露 | `secrets/` 权限、不回显、不进日志/导出、日志脱敏 |
| 保存规则导致连接断开 | 增量 Apply + 动态 `GetCertificate`（M3 重点） |
| 80/443 被飞牛自身服务占用 | 绑定失败可见化 + 明确提示改用高位端口 / 由 UPnP 做外部端口映射 |
| 与已安装的 fnUPnP / fnProxy 共存冲突 | 不同 appname 与 Socket 路径；但业务端口与映射可能撞车 → 首次启动检测并提示（D1） |
| 32 位 ARM 兼容 | 沿用 `GOARM=6`；真机或 QEMU 冒烟 |
