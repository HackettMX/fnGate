# fnGate 代码审查报告

审查时间：2026-11-21
审查范围：`src/` 全部 Go 后端 + `src/static/` 前端
基线：v1.2.16（飞牛系统 HTTPS 同步已整体回滚，代码等同 v1.2.7）

---

## 结论摘要

代码整体**结构清晰、注释充分**，对国内 NAS 场景（DNSPod 空 NS、fake-ip、CNAME 落点）的打磨很细致，安全设计方向正确（同源校验 + CSRF、私钥仅 POST 导出、配置备份不含凭据、secret 独立 0700 目录、原子落盘）。

主要问题集中在四类：
1. **本地多用户越权**（socket 0666）
2. **静默失效**（定时任务 panic 吞掉、EventBus 竞态、ACME worker 关闭不等待）
3. **资源泄漏**（反代 Transport、TCP 转发 goroutine、HTTP 无超时）
4. **功能冗余**（DNS 解析查询/体检、多处重复代码与死代码）

---

## 高严重度

### H1 · Unix Socket 权限 0666，同机任意用户可接管管理接口
- **位置**：`src/main.go:135`、`src/api/server.go:113-118`、`src/api/security.go:68-72`
- **问题**：任何本机用户都能 `curl --unix-socket` 请求 `GET /` 拿到 HTML 里的 `csrf-token`，随后调用任意写接口——包括 `POST /api/cert/{id}/export`（导出私钥）、增删反代路由、写 DNS API 凭据。CSRF 防跨站，防不住同机多用户。
- **建议**：socket 改 `0660`，属主/属组设为运行账号与网关进程组（新增 `FNGATE_SOCKET_GROUP` 配置）；若必须兼容 0666，则对 export/backup/凭据写入加一次性 token 或短时效 token，并把 token 改为 `HttpOnly` Cookie + 服务端校验来源。

### H2 · 定时任务 panic 被静默吞掉，续期会无声失效
- **位置**：`src/core/scheduler.go:94-102`
- **问题**：ACME 自动续期、UPnP 补发、健康检查都跑在调度器里。任何一次 panic 后任务**永久停止且无任何日志**，用户只能看到「证书到期了却没续期」。
- **建议**：给 `Scheduler` 注入 `*core.Logger`，`recover` 中记录 `task.name` + panic 值 + `debug.Stack()`，并发布 error 事件；对续期这类关键任务做失败计数告警。

### H3 · EventBus.Subscribe 存在 send-on-closed-channel 竞态（且是死代码）
- **位置**：`src/core/event.go:39-49`（Publish 解锁后发送）、`79-92`（Unsubscribe 锁外 close）
- **问题**：Publish 复制 targets 解锁 → Unsubscribe 删除并 close → Publish 向已关闭通道发送 → **panic 终止进程**。全库 `Subscribe`/`Recent` 零调用。
- **建议**：直接删除整套未使用机制（最简、无风险）；若要保留，把 `close(ch)` 移入持锁区，或改为只删除不关闭 + `done` 通道配合 `select` 发送。

### H4 · 「一键体检」接口未限制服务器数量与总耗时（本次已随功能删除）
- **位置**：原 `src/acme/resolve.go:315-365`
- **问题**：请求体 `servers` 可塞几十上百台，单请求同步执行大量 5s DNS 查询，可长时间占用 handler。
- **建议**：若将来恢复该能力，需复用 8 台上限并传 `context.Context` 做整体超时，DNS 查询改 `ExchangeContext`。

## 中严重度

### M1 · 反代配置变更时 Transport 未关闭
- **位置**：`src/proxy/http.go:99-108`、`174-181`；`src/proxy/manager.go:142`
- **问题**：每条路由一个 `http.Transport`，`pruneCache` 只 `Delete` 未 `CloseIdleConnections`；反复编辑路由会累积 keep-alive 连接与 goroutine。
- **建议**：失效条目删除前调用 `rp.CloseIdleConnections()`；或改为全局共享 Transport（按 `VerifyBackendTLS` 区分两份）。

### M2 · 飞牛证书导入路径校验不防符号链接
- **位置**：`src/cert/fnos.go:392-441`
- **问题**：`filepath.Abs` 不解析 symlink，白名单目录内若有指向外部的软链，root helper 会越界读取。
- **建议**：`os.ReadFile` 前 `filepath.EvalSymlinks`，对真实路径再做一次 `pathAllowed`；`Open` 后用 `f.Stat()` 复核防 TOCTOU。

### M3 · 日志脱敏覆盖不全且会误杀
- **位置**：`src/core/scheduler.go:135-144`
- **问题**：漏掉 `access_key`/`apiKey`/`eab_hmac`；无冒号分隔的值不脱敏；命中即替换整行，把「DNS Token 无效（401）」这类无秘密提示也吞掉。
- **建议**：用正则精确匹配 `key=value` 中的值替换为 `***`，不吞整行。

### M4 · DNS 服务商「更新凭据」先写 secret 后改状态
- **位置**：`src/acme/dnsapi.go:323-360`
- **问题**：`Store.Update` 失败时新凭据已覆盖旧文件，但 `CredentialRef`/`AccountHint` 仍是旧值，界面与行为不一致。
- **建议**：写临时 ref，`Store.Update` 成功指向新 ref 后再删旧 ref；或失败分支恢复旧 secret 字节。

### M5 · 备份下载接口错误路径仍带附件头
- **位置**：`src/api/system.go:149-160`
- **问题**：先设 `Content-Disposition` 再 `Store.Export`，失败时下载到名为 `fngate-state.json` 的 JSON 错误。
- **建议**：先写入内存 `bytes.Buffer`，成功后再统一设置响应头并写出。

### M6 · ACME worker 关闭不等待
- **位置**：`src/acme/manager.go:72-85`、`src/main.go:169`
- **问题**：`Close()` 只 `close(done)`，卡在 `Obtain`（分钟级）的 worker 不会被唤醒，优雅退出形同虚设。
- **建议**：保存运行中的 `context.CancelFunc`，`Close()` 取消全部并 `WaitGroup.Wait()`（带总超时）。

### M7 · TCP 转发 goroutine 泄漏 / 半开
- **位置**：`src/proxy/tcp.go:103-109`
- **问题**：客户端→后端方向的 goroutine 不受另一方向结束控制；一侧 `io.Copy` 返回后未关闭另一侧。
- **建议**：任一方向返回后 `CloseRead`/`CloseWrite` 两端，用 `sync.Once` 幂等；为后端连接设 `SetDeadline`。

### M8 · HTTP 服务缺读/写/空闲超时
- **位置**：`src/main.go:123`、`src/proxy/manager.go:196`
- **问题**：仅 `ReadHeaderTimeout: 10s`，慢客户端可长期占用连接与 goroutine。
- **建议**：补 `ReadTimeout`/`WriteTimeout`/`IdleTimeout`，`MaxHeaderBytes` 设 1<<20。

### M9 · DNS 预检串行无限时上限
- **位置**：`src/acme/nscheck.go:121-139`、`284-290`
- **问题**：N 台 DNS × 多级 `findZone` × 5s 超时全部串行，最坏阻塞单 worker 数十秒，期间其它订单无法推进。
- **建议**：整体 context 超时（如 15s）并向下传递；customResolvers 加数量上限。

## 低严重度 / 代码质量

- **L1 重复代码**：`newID()`/`nowText()`/`minInt()` 在 cert、acme、proxy 各写一份；`MatchDomain` 在 `cert/util.go:152` 与 `proxy/util.go:98` 近乎相同 → 下沉到 `core`。
- **L1 无效分支**：`acme/dnsapi.go:214-218` 的 `if/else` 两分支完全相同 → 一行赋值。
- **L1 死代码**：`acme/nscheck.go:211-228` `lookupTXT`、`Scheduler.TrimLines`、`EventBus.Recent/Subscribe` 生产零调用 → 删除。
- **L2 笔误**：`acme/nscheck.go:41` `resolverCachAt` → `resolverCacheAt`；`src/cert/api.go:351` 函数起始与首语句同行。
- **L3 错误信息泄露**：`proxy/http.go:163-166,222-223` 把后端 URL 与底层错误原样回显 → 对外统一「无法连接后端」+ 错误码，详情只进日志。
- **L4 竞态细节**：`cert/manager.go:279-314` `fallbackCert` 双检锁无 `sync.Once`；`cert/fnos.go:500-520` `findSiblingKey` 注释说「唯一」实际返回第一个匹配，可能选错私钥。
- **L5 权限面**：`cert/fnos.go:557-580` `chownTree` 递归 chown 整个 certs/secrets，包括用户手动上传的证书 → 只 chown 本次快照涉及的文件。
- **L5 多实例**：`main.go:129-135` 启动即删 socket，两个实例会互删 → 用 PID 文件或 flock 防多实例。

## 已回滚功能的残留检查

**结论：干净。** `src/` 下已无 `deployer`、`fnos_push`、`daemon_facts`、`network_service`、`trim_nginx` 任何引用。

后续根据用户要求，1.2.17 又进一步移除了 1.2.7 遗留的**飞牛证书只读导入**（`--cert-sync` 与 `cert/fnos.go`）：证书管理现在只涉及本应用申请、上传、自签的证书，完全不读取飞牛系统证书目录。本报告下面 M2 条目（fnos 软链校验）与相关建议因此已不再适用，保留仅作历史记录。

## 修复优先级建议

1. H1（本地越权，改动小、风险高）
2. H3 + L1 死代码（顺手消除 panic 隐患）
3. H2（续期静默失效）
4. M1 + M7 + M8（连接与 goroutine 泄漏）
5. M2 + M4（凭据与路径安全）
6. 其余按模块分批

本次已实施：DNS 工具功能下线（H4 随之消失）、UI 重构与移动端适配、以及上述标注的高价值缺陷修复（详见发版说明）。
